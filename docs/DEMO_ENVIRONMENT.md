# Demo Environment

## What the demo needs

Python 3.11+ and this repository. Nothing else. No network, no phones, no models, no
containers.

```bash
make demo
```

## What each optional layer adds

| Layer | Command | Needs | If it fails |
|---|---|---|---|
| Core demo | `make demo` | Python only | Nothing to fall back to — but it has no dependencies to break |
| Simulator | `make simulate` | Python only | Show the JSON report from `reports/` |
| Gateway | `make run-backend` | Python + fastapi | Skip; the mesh does not need it |
| Dashboard | `make run-dashboard` | Node + `npm install` | Skip; it is the optional layer by design |
| Android | — | SDK, Gradle, JDK 17/21, two devices | **Unavailable.** Say so plainly |

## Deliberate offline posture

Airplane mode is a fair demonstration, not a limitation: the entire product path runs
with no network stack involved. If someone asks you to prove it, turn the wifi off and
run `make demo` again.

## Reset between runs

```bash
make reset-demo
```

Deletes the gateway database and reseeds seven simulated resources. It refuses to
delete a database that is not a known demo file unless `--force` is given.

## Fixtures

`test-fixtures/` holds incidents generated by the real pipeline
(`make fixtures` regenerates them), including Tamil and Hindi reports and a P3 logistics
report used to demonstrate that routine traffic never pre-empts a P0.
